# Прототипы редизайна `/admin`

Пять самостоятельных HTML-страниц на тех же токенах, что `src/styles/system.css` (`base.css` —
копия палитры и типографики, `mock.js` — общие данные и скриптовый «эфир», который за 40 секунд
имитирует SSE: заходят игроки, меняется счёт, Kira правит две настройки, Bobr выгоняет игрока,
падает TPS). Открывать из checkout (шрифты берутся из `node_modules`).

Каждый прототип отвечает на три вопроса пользователя по-своему: как выглядит, где кнопка
«Сохранить», как видно чужие изменения.

| #   | Файл               | Каркас                                              | Модель сохранения                                                             | Чужие изменения                                                                | Кому подходит                                |
| --- | ------------------ | --------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------- |
| 1   | `01-pult.html`     | Боковое меню + живая полоса статуса                 | Автосохранение по полю при потере фокуса, «сохранено» у поля, тост-отмена     | Поле подсвечивается, подпись «Kira · только что», тост                         | Владелец/админ за монитором, много настроек  |
| 2   | `02-tray.html`     | Верхние вкладки + правая колонка «Сейчас»           | Один лоток внизу на всю панель: список изменений «было → стало», одна кнопка  | Если Kira меняет то же поле — конфликт в лотке: «взять её» или «оставить своё» | Когда правки надо осмысленно собирать пачкой |

## Общее для всех

- Ноль скруглений, одна янтарная лампа, моно только у чисел и кодов — по `DESIGN.md`.
- Состояние словом, не только цветом: «сохраняем / сохранено / Kira · только что / ошибка».
- Оптимистичные правки: интерфейс меняется сразу, сервер подтверждает; при отказе значение
  откатывается и показывается причина (в моке 1 из 12 записей падает).
- Опасные действия (мастерская, бан, стоп матча, прервать всё) всегда с подтверждением.

## Транспорт реальных данных (одинаков для всех вариантов)

Один канал `GET /api/admin/events` на **Server-Sent Events** вместо WebSocket: Astro/Node его уже
умеет без зависимостей, он проходит через reverse proxy и переподключается сам
(`EventSource`). Сервер шлёт `status`, `rooms`, `settings`, `audit`, `presence`, `health`;
источники — `fs.watch` на `status.json`/`settings.json`/`applied.json`, тот же опрос комнат, что
сейчас, и хук после каждой записи в `admin_audit`. Присутствие — heartbeat `POST
/api/admin/presence {tab}` раз в 30 с. Сохранение остаётся обычным `PUT`/`POST` с
`expectedRevision`: 409 превращается в конфликт, как в прототипе 2.
